# Calcium Module Registry Specification (Draft)

## Overview

Manage module metadata in a GitHub repository, with registration through a PR (Pull Request) based system.

## Design Principles

1. **GitHub repository as registry** - No server required, high transparency
2. **Application-based** - Register modules via PR, merge after review
3. **Metadata only management** - Actual code stays in author's repository
4. **Static hosting** - Deployable via GitHub Pages

---

## Registry Structure

### Repository: `calcium-lang/modules`

Author name-based hierarchical structure for scalability.

```
calcium-lang/modules/
├── README.md
├── index/
│   ├── all.toml            # Full module name list (lightweight)
│   ├── A.toml              # List of modules by authors starting with A
│   ├── B.toml
│   └── ...
├── packages/
│   ├── J/
│   │   └── JO/
│   │       └── JOHNDOE/
│   │           ├── author.toml     # Author information
│   │           ├── http/
│   │           │   ├── meta.toml
│   │           │   ├── 1.0.0.toml
│   │           │   └── 1.1.0.toml
│   │           └── json-parser/
│   │               ├── meta.toml
│   │               └── 2.0.0.toml
│   └── S/
│       └── SA/
│           └── SARAHDEV/
│               ├── author.toml
│               └── async-utils/
│                   ├── meta.toml
│                   └── 0.5.0.toml
└── .github/
    └── workflows/
        └── validate.yml
```

### Path Structure

```
packages/{1-letter}/{2-letters}/{AUTHOR}/{MODULE}/meta.json
```

Examples:
- `JOHNDOE/http` → `packages/J/JO/JOHNDOE/http/meta.json`
- `SARAHDEV/async-utils` → `packages/S/SA/SARAHDEV/async-utils/meta.json`

### Benefits

- **Scalability**: Prevents large file concentrations in single directories
- **PR conflict avoidance**: Paths separated by author
- **Easy browsing**: Organized by author
- **CPAN-style**: Proven structure

## Metadata Format

### packages/{A}/{AB}/{AUTHOR}/{MODULE}/meta.toml

```toml
name = "http"
author = "JOHNDOE"
description = "HTTP client library for Calcium"
repository = "https://github.com/johndoe/calcium-http"
license = "MIT"
keywords = ["http", "client", "network"]
latest = "1.1.0"

# Dependencies (optional)
[dependencies]
"SARAHDEV/json" = "^1.0.0"
"CALCIUM/core" = ">=2.0.0"
```

### Dependencies Format

Dependencies are specified as a map of module names to version constraints:

```toml
[dependencies]
"author/module" = "version_constraint"
```

> **Note:** Core modules (`core.*`) are part of the standard library and do NOT need to be declared as dependencies. Only external/third-party modules should be listed.

**Supported version constraint operators:**

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` or none | Exact version | `"1.2.3"` |
| `^` | Compatible with (same major) | `"^1.2.3"` means `>=1.2.3 <2.0.0` |
| `~` | Approximately (same minor) | `"~1.2.3"` means `>=1.2.3 <1.3.0` |
| `>=` | Greater than or equal | `">=1.0.0"` |
| `<=` | Less than or equal | `"<=2.0.0"` |
| `>` | Greater than | `">1.0.0"` |
| `<` | Less than | `"<2.0.0"` |
| `*` | Any version | `"*"` |
| `latest` | Latest version | `"latest"` |

**Special case for 0.x versions:**
- `^0.2.3` means `>=0.2.3 <0.3.0` (more restrictive)

### packages/{A}/{AB}/{AUTHOR}/{MODULE}/{VERSION}.toml

File list and hashes per version:

```toml
version = "1.1.0"
published = "2025-01-20"
entry = "mod.ca"
base_url = "https://raw.githubusercontent.com/johndoe/calcium-http/v1.1.0/"

[files]
"mod.ca" = "a1b2c3d4e5f6..."
"client.ca" = "b2c3d4e5f6a1..."
"server.ca" = "c3d4e5f6a1b2..."
"internal/utils.ca" = "d4e5f6a1b2c3..."
```

File path examples:
- `packages/J/JO/JOHNDOE/http/meta.toml` (module info)
- `packages/J/JO/JOHNDOE/http/1.0.0.toml` (v1.0.0 file list)
- `packages/J/JO/JOHNDOE/http/1.1.0.toml` (v1.1.0 file list)

### File Resolution Flow

```
use "https://ca.land/JOHNDOE/http@1.1.0/client.ca"!;
```

1. **Get metadata**: `JOHNDOE/http/1.1.0.json`
2. **Search files**: `files["client.ca"]` → get hash value
3. **Build actual URL**: `base_url + "client.ca"`
   → `https://raw.githubusercontent.com/johndoe/calcium-http/v1.1.0/client.ca`
4. **Download & verify hash**
5. **Cache & load**

### Index Files

#### index/all.toml (Lightweight index)

For module search. Names and authors only. Auto-generated by CI.

```toml
version = "1"
updated = "2025-01-22T10:00:00Z"
count = 1523

[[modules]]
name = "http"
author = "JOHNDOE"
latest = "1.1.0"

[[modules]]
name = "json-parser"
author = "JOHNDOE"
latest = "2.0.0"

[[modules]]
name = "async-utils"
author = "SARAHDEV"
latest = "0.5.0"
```

#### index/{A-Z}.toml (Author-based index)

Index split by first letter. Auto-generated by CI.

```toml
# index/J.toml

[authors.JOHNDOE]
modules = ["http", "json-parser"]
path = "J/JO/JOHNDOE"

[authors.JANEDOE]
modules = ["csv-reader"]
path = "J/JA/JANEDOE"
```

#### packages/.../author.toml (Author information)

```toml
# packages/J/JO/JOHNDOE/author.toml
name = "JOHNDOE"
display_name = "John Doe"
github = "johndoe"
registered = "2025-01-15"
modules = ["http", "json-parser"]
```

### Module Name Uniqueness

Module names are unique within **author scope**:

```calcium
// Same name but different authors are different modules
use "https://ca.land/JOHNDOE/http@1.0.0/mod.ca"!;
use "https://ca.land/SARAHDEV/http@2.0.0/mod.ca"!;  // Different module
```

URL structure:
```
https://{host}/{AUTHOR}/{MODULE}@{VERSION}/{PATH}
```

## Module Registration Flow

### 1. Author creates module

```
my-calcium-lib/
├── mod.ca              # Entry point
├── client.ca
├── server.ca
└── README.md
```

### 2. Create tag on GitHub

```bash
git tag v1.0.0
git push origin v1.0.0
```

### 3. Calculate file hashes

```bash
# Calculate SHA256 for each file
sha256sum mod.ca client.ca server.ca
# a1b2c3d4...  mod.ca
# b2c3d4e5...  client.ca
# c3d4e5f6...  server.ca
```

### 4. Submit PR to registry

```bash
# Fork calcium-lang/modules
git clone https://github.com/yourname/modules
cd modules

# Create directory (Y/YO/YOURNAME/my-lib/)
mkdir -p packages/Y/YO/YOURNAME/my-lib

# Module info (first time only)
cat > packages/Y/YO/YOURNAME/my-lib/meta.toml << 'EOF'
name = "my-lib"
author = "YOURNAME"
description = "My awesome library"
repository = "https://github.com/yourname/my-calcium-lib"
license = "MIT"
keywords = ["utility"]
latest = "1.0.0"
EOF

# Version info (file list and hashes)
cat > packages/Y/YO/YOURNAME/my-lib/1.0.0.toml << 'EOF'
version = "1.0.0"
published = "2025-01-22"
entry = "mod.ca"
base_url = "https://raw.githubusercontent.com/yourname/my-calcium-lib/v1.0.0/"

[files]
"mod.ca" = "a1b2c3d4..."
"client.ca" = "b2c3d4e5..."
"server.ca" = "c3d4e5f6..."
EOF

git add .
git commit -m "Add YOURNAME/my-lib@1.0.0"
git push origin main
# → Create PR
```

### 4. Automatic validation (CI)

Validation by GitHub Actions on PR:

- [ ] meta.json format check
- [ ] URL reachability verification
- [ ] Checksum validation
- [ ] Name duplication check
- [ ] License documentation confirmation

### 5. Review & merge

Maintainer reviews and merges → reflected in registry

## Version Addition Flow

New version for existing module:

```bash
# 1. Create new tag in your repository
git tag v1.1.0
git push origin v1.1.0

# 2. Calculate file hashes
sha256sum mod.ca client.ca server.ca new-feature.ca

# 3. Add new version file in registry
cat > packages/Y/YO/YOURNAME/my-lib/1.1.0.toml << 'EOF'
version = "1.1.0"
published = "2025-01-25"
entry = "mod.ca"
base_url = "https://raw.githubusercontent.com/yourname/my-calcium-lib/v1.1.0/"

[files]
"mod.ca" = "..."
"client.ca" = "..."
"server.ca" = "..."
"new-feature.ca" = "..."
EOF

# 4. Update latest in meta.toml
# latest = "1.1.0"

git commit -m "Add YOURNAME/my-lib@1.1.0"
# → Create PR
```

## URL Resolution

> **Note**: `ca.land` is a placeholder domain. Actual implementation may use `calcium-modules.github.io` or an acquired domain.

### URL Format

```
https://{HOST}/{AUTHOR}/{MODULE}@{VERSION}/{PATH}
```

### User Code

```calcium
use "https://ca.land/JOHNDOE/http@1.0.0/client.ca"!;  // Placeholder
// Actually:
use "https://calcium-modules.github.io/JOHNDOE/http@1.0.0/client.ca"!;
```

### Host (Placeholder) Role

`ca.land` (placeholder) via GitHub Pages or Cloudflare Workers:

1. Receives request to `https://ca.land/JOHNDOE/http@1.0.0/client.ca`
2. Gets `JOHNDOE`'s path from `index/J.toml`
3. References `packages/J/JO/JOHNDOE/http/1.0.0.toml`
4. Gets `base_url` + `files["client.ca"]`
5. Redirects:
   ```
   → https://raw.githubusercontent.com/johndoe/calcium-http/v1.0.0/client.ca
   ```

### Static Hosting Option

Deploy via GitHub Pages:

```
https://calcium-lang.github.io/modules/JOHNDOE/http@1.0.0/client.ca
                                    ↓ (redirect)
https://raw.githubusercontent.com/johndoe/calcium-http/v1.0.0/client.ca
```

## Validation Workflow

### .github/workflows/validate.yml

```yaml
name: Validate Package

on:
  pull_request:
    paths:
      - 'packages/**'

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Validate meta.json
        run: |
          # JSON format check
          # Required fields check
          # URL reachability confirmation
          # Checksum verification
          ./scripts/validate.sh

      - name: AI Review
        uses: calcium-lang/ai-review-action@v1
        with:
          package-path: ${{ github.event.pull_request.changed_files }}
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

      - name: Auto Merge (if passed)
        if: steps.ai-review.outputs.status == 'pass'
        run: gh pr merge --auto --squash

      - name: Request Human Review (if flagged)
        if: steps.ai-review.outputs.status != 'pass'
        run: |
          gh pr comment --body "AI Review flagged this PR for human review."
          gh pr edit --add-label "needs-human-review"
```

## AI Review

PRs are reviewed automatically by AI by default. Human review only for exceptional cases.

### Review Criteria

| Criteria | Check Content |
|----------|---------------|
| **Security** | Dangerous system calls, file operations, network communication validity |
| **Malicious intent** | Obfuscated code, hidden features, data collection, backdoors |
| **Purpose clarity** | Match between README/description and actual code, clear functionality |
| **License** | License documentation and validity |

### License Policy

**Default MIT enforcement rule:**

- If no license specified → **MIT license auto-applied**
- If you want non-MIT → explicitly specify the license

```json
// meta.json
{
  "license": "MIT",           // Required to specify
  "license": "Apache-2.0",    // Or other license
  "license": "UNLICENSED"     // Proprietary (requires explanation)
}
```

**AI check items:**

| State | Judgment |
|-------|----------|
| No `license` field | → Auto-set MIT, PASS with warning |
| SPDX identifier specified | → PASS as-is |
| No LICENSE file in repository | → Warning, meta.json value is authoritative |
| meta.json and LICENSE file conflict | → Human review |
| Unknown license string | → Human review |

**Recommended licenses:**

- MIT - Simple, widely used (default)
- Apache-2.0 - Has patent clause
- BSD-3-Clause - Similar to MIT
- GPL-3.0 - Copyleft (watch dependencies)

### AI Review Flow

```
PR created
  ↓
CI: Format check (JSON, URL reachability, checksum)
  ↓
AI Review:
  1. Get source code (from URL)
  2. Security scan
  3. Malicious pattern detection
  4. Purpose and implementation consistency check
  ↓
┌─ PASS → Auto merge
└─ FAIL/WARN → Escalate to human review
```

### AI Review Result

```json
{
  "status": "pass",
  "security": {
    "score": "safe",
    "notes": []
  },
  "malice": {
    "score": "none",
    "notes": []
  },
  "purpose": {
    "score": "clear",
    "declared": "HTTP client library",
    "actual": "HTTP client with GET/POST support",
    "match": true
  },
  "license": {
    "declared": "MIT",
    "file_found": true,
    "consistent": true,
    "auto_applied": false
  },
  "summary": "Safe HTTP client library with clear purpose and MIT license."
}
```

**Result example when license not specified:**

```json
{
  "status": "pass",
  "license": {
    "declared": null,
    "file_found": false,
    "consistent": true,
    "auto_applied": true,
    "note": "No license specified. MIT license auto-applied."
  },
  "summary": "...(warning: MIT license was auto-applied)"
}
```

### Escalation Conditions

- Security score is `warning` or higher
- Malice score is `suspicious` or higher
- Low purpose match
- AI deferred judgment

### Prohibited Patterns (Auto-reject)

- `os.exec` etc. arbitrary command execution (without legitimate reason)
- Reading credentials from environment variables (not explicit)
- Data transmission to external URLs (not explicit)
- Base64 encoded execution code
- Dynamic loading of dependency modules

## Security Considerations

1. **Checksum required** - Tampering detection
2. **HTTPS only** - Man-in-the-middle attack prevention
3. **AI review required** - Automatic detection of malicious code
4. **Author authentication** - Linked to GitHub account
5. **Version immutability** - Version content cannot be changed after publication
